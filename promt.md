Ты работаешь с существующим научным проектом:

https://github.com/yapimiu/Hybrid_interface

Твоя задача — расширить этот проект полноценной подсистемой обнаружения P300 для интерфейса «мозг — компьютер».

**Не создавай новое приложение и не переписывай существующий интерфейс.**

В проекте уже реализованы:
- Приём ЭЭГ через LSL в `app/viewer.py`.
- Класс `LSLReceiver(QThread)`.
- Передача данных через `chunk_received`.
- Отображение многоканальной ЭЭГ с помощью PyQtGraph.
- Сохранение исходной ЭЭГ с временными метками через `app/recording.py`.
- Сборка приложения под Windows и macOS.

Необходимо интегрировать новую подсистему P300 в существующую архитектуру.

### Требования

1. Изучи все существующие файлы проекта, зависимости и тесты.
2. Сохрани текущую функциональность просмотра, регистрации и экспорта ЭЭГ.
3. Создай независимый модуль `app/p300/`.
4. Реализуй непрерывный буфер многоканальной ЭЭГ с временными метками.
5. Добавь получение LSL-маркеров визуальных стимулов с идентификаторами объектов.
6. Реализуй синхронизацию событий с ЭЭГ.
7. Реализуй предварительную обработку с MNE-Python и SciPy.
8. Добавь выделение эпох относительно начала стимулов, контроль качества и коррекцию базовой линии.
9. Реализуй усреднение ERP по объектам и визуализацию результатов.
10. Реализуй процедуру индивидуальной калибровки и обучение Shrinkage LDA и xDAWN + LDA на реальных размеченных данных.
11. Добавь онлайн-классификацию и накопление оценок по объектам.
12. Интегрируй результаты с существующим Qt-интерфейсом.
13. Обеспечь сохранение экспериментальных данных, меток, конфигурации и результатов.
14. Добавь модульные и интеграционные тесты.
15. Проверь отсутствие утечки данных между обучением и тестированием.

Программа разрабатывается для научно-исследовательского проекта и должна обеспечивать воспроизводимость вычислений.

Синтетические данные разрешены только для автоматизированных проверок. Основной конвейер должен работать с реальными записями ЭЭГ.

Если нет потока маркеров или откалиброванной модели, выводи диагностическое состояние вместо фиктивного результата.

Не проводи ресурсоёмкие вычисления в главном потоке Qt.

### Порядок работы

Сначала выполни технический аудит существующего кода. Затем реализуй независимое вычислительное ядро P300 с тестами. После этого подключи его к действующему LSL-приёмнику.

Сохраняй работоспособность проекта после каждого этапа.

Результат должен быть представлен реальными изменениями исходного кода, тестами и документацией, а не общими рекомендациями.

Не объявляй алгоритм валидированным, пока не проведено тестирование на независимых реальных размеченных данных.
