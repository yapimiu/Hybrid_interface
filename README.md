# Hybrid Interface

Приложение принимает LSL поток типа `EEG` или `Signal` и показывает сигналы каналов в окне Qt. Из нескольких потоков выбирается самый новый. Поток, который после подключения 5 секунд не передаёт отсчёты (НейроСпектр оставляет такой после каждой остановленной записи), пропускается при следующем поиске. При обрыве соединения поиск запускается снова.

Пошаговая инструкция пользователя — куда нажимать, чтобы получить запись ЭЭГ, массив P300 и архив эксперимента: [docs/USER_GUIDE.md](docs/USER_GUIDE.md).

## Установка и запуск

```bash
git clone https://github.com/yapimiu/Hybrid_interface.git
cd Hybrid_interface
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/install_lsl.py
python -m app.main
```

На Windows активация окружения: `.venv\Scripts\activate`.

Рекомендуется Python 3.12. На macOS/Windows скрипт install_lsl.py устанавливает
закреплённую нативную liblsl только внутрь venv. На Linux установите liblsl
для своей платформы отдельно.

## P300

Основной сценарий находится во вкладке **«Единый эксперимент»**: общая кнопка
запускает стимулятор, подключает маркеры, проводит серию проб и сохраняет
EEG, события, ERP и результаты в отдельный архив. Каналы/единицы задаются
на вкладке P300. Инструкция: [docs/EXPERIMENT.md](docs/EXPERIMENT.md).
Локальная обновлённая Windows-сборка: `dist/unified/HybridInterface.exe`.
Обычная команда сборки по-прежнему создаёт `dist/HybridInterface.exe`.

В отдельную вкладку встроено исходное Qt-окно анализатора из
[hybrid-bci-p300-ssvep](https://github.com/SergPronin/hybrid-bci-p300-ssvep),
коммит `4e5dc7c0165da40c1ec2eacd633032c2415e31ec`.
Сохранены его алгоритмы, профили, ERP-графики, выбор цели, загрузка записей
и экспорт. Прежняя реализация LDA/xDAWN удалена. Новые классификаторы
и новые процедуры обучения не создаются.

Нужен внешний LSL-стимулятор с маркерами `-1|trial_start|target=N`,
`100|on` … `108|on`, `-2|trial_end` (также поддержаны ID `0..8`).
EEG для P300 приходит из того же приёмника,
что обслуживает графики и исходную CSV-запись.

На вкладке «Запуск и проверка» можно запустить оригинальный стимулятор,
операторскую программу протокола или синтетическую проверку Пронина.
Для оригинального стимулятора нужен отдельный Python 3.10 с
`requirements-pronin.txt` (`setup_pronin_windows.bat` на Windows).
Выберите его Python в этой вкладке. Запуск стимулятора использует
`--no-analyzer`, поскольку анализатор уже встроен.

Порядок работы и границы проверки: [docs/P300.md](docs/P300.md).
Реальные записи и энцефалограф для установки и автоматических проверок не нужны.

## Массив данных

Последний принятый блок доступен в `window.signal_array` (`numpy.ndarray`). Его форма — `(число отсчётов, число каналов)`. Это сырые значения LSL; новый блок заменяет предыдущий. До первого блока массив пустой. Переменная принадлежит экземпляру `SignalViewerWindow` в `app/viewer.py` и обновляется в главном потоке Qt.

Графики сохраняют только данные текущего окна отображения. Все каналы показываются автоматически; масштаб по X и Y и показатели под графиками доступны в интерфейсе. Окно можно прокручивать вверх и вниз, в том числе колесом мыши поверх графиков.

Под графиками отображается полный последний принятый массив с его размером. Значения можно выделить и скопировать. Поле обновляется каждые 250 мс и показывает сырые значения всех каналов.

Кнопка «Сохранить графики (PNG)» сохраняет изображение со всеми каналами, включая те графики, которые находятся ниже видимой области прокрутки.

Встроенного генератора или тестового LSL потока нет. Приложение принимает данные внешнего источника.

## Сумма эпох по объектам (массив P300)

Каждая вспышка объекта даёт эпоху: отсчёты от вспышки (с baseline до неё) × каналы ROI.
Эпохи одного объекта складываются поточечно — первый отсчёт первой вспышки с первым
отсчётом второй и т. д. Для каждого объекта получается одна кривая на каждый канал.

Результат выводится под графиками вкладки P300 и во вкладке «Единый эксперимент»
(текущая / последняя проба). Значения можно выделить и скопировать. Переключатель
«Вывод» выбирает вариант:

1. **Единый массив** — все суммы в одной таблице: строки — отсчёты от вспышки,
   столбцы — `объект_канал` (например, `4_Cz`). В коде: `window.p300_unified_array`.
2. **Одно число на объект** — средняя амплитуда усреднённой кривой (сумма / число
   вспышек) после коррекции baseline в окне решения анализатора (поля X/Y вкладки P300,
   по умолчанию 550–725 мс), по всем каналам ROI. Отмечен объект с максимумом.
   В коде: `window.p300_object_numbers`. Это описательная мера, а не откалиброванный
   классификатор; основной выбор объекта по-прежнему делает анализатор Пронина.

Трёхмерный массив сумм `(объекты, отсчёты, каналы)` доступен как `window.p300_sum_array`.
Эпохи берутся у анализатора Пронина без изменений: полосовой фильтр и CAR уже применены,
отбраковка артефактов к сумме не применяется. Реализация — `app/bci/erp_sums.py`.

В архиве эксперимента для каждой пробы сохраняются `erp_sums.npz` (всё вместе),
`erp_unified.csv` (вариант 1) и `erp_numbers.csv` (вариант 2); числа также записываются
в `result.json` (`sum_numbers`).

## Сохранение в файл

После подключения потока нажмите «Начать запись в CSV» и выберите файл. Все следующие принятые блоки сохраняются до нажатия «Остановить и сохранить». Данные записываются по мере получения, без накопления всей записи в памяти. При отключении или смене потока, а также при закрытии приложения запись завершается; для нового потока запись нужно начать заново.

В CSV первая строка содержит имена столбцов: `lsl_timestamp_s` и имена каналов. Каждая следующая строка — один отсчёт: исходное время LSL в секундах и сырые значения всех каналов. Время LSL — монотонная временная метка источника, а не дата и время на часах. Разделитель — запятая, десятичный разделитель — точка, кодировка — UTF-8 с BOM. Значения сохраняются без очистки и ограничения амплитуды, применяемых только к графикам.

## Сборка

```bash
pip install -r requirements-dev.txt
python scripts/build_app.py
python scripts/check_bundle.py
```

На macOS результат — `dist/Hybrid Interface.app`. На Windows — `dist/HybridInterface.exe`.

Для автоматической установки зависимостей и сборки на Windows запустите `build_windows.bat`. Подробности — в `BUILD_WINDOWS.md`.

GitHub Actions автоматически собирает приложения для Windows и macOS после отправки изменений в `main`. Настройки находятся в `.github/workflows/build.yml`. Готовые архивы доступны в разделе Actions → Build applications → Artifacts.

## Структура

- `app/viewer.py` — приём LSL, графики и вывод массива.
- `app/recording.py` — запись данных в CSV.
- `p300_analysis/` — неизменённые модули P300 из репозитория Сергея Пронина.
- `app/bci/` — общий EEG-приёмник, управление экспериментом, архив сессии, P300-окно и процессы.
- `vendor/hybrid_bci/` — исходные программы стимулятора и протокола Пронина.
- `validation/` — исходная синтетическая проверка P300 Пронина.
- `app/main.py` — точка входа.
- `scripts/build_app.py` — сборка приложения.
- `scripts/install_lsl.py` — установка закреплённой нативной LSL в venv.
- `hybrid_interface.spec` — настройки PyInstaller.

Проверки: `python -m pytest tests -q`. Реальная локальная передача LSL проверяется
отдельно с переменной окружения `RUN_LSL_NETWORK=1`. Искусственные сигналы
используются только для проверки ПО и не выдаются за реальную ЭЭГ.
