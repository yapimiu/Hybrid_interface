# Технический аудит до интеграции P300

Изучены все исходные файлы, тесты, зависимости, PyInstaller spec, CI и инструкции
сборки. Задание находится в `promt.md` (имя сохранено).

- `LSLReceiver(QThread)` ищет EEG/Signal и передаёт сырые отсчёты и исходные
  timestamps через `chunk_received`. Этот контракт нужен графикам и CSV.
- `SignalViewerWindow` хранит только последний массив и короткую очередь для
  графиков. Это не буфер для выделения эпох. Фильтрация и обучение в GUI недопустимы.
- `CsvRecording` пишет все блоки без изменения значений и времени; существующие
  тесты проверяют NaN/Inf, ошибки формы и независимость записей.
- Маркеров, коррекции часов, информации о единицах, калибровки и моделей нет.
  Номинальная частота может быть нулевой: такие потоки пригодны для старого
  просмотрщика, но не для P300 без ресемплинга по подтверждённой частоте.
- PyInstaller исключает SciPy. Для нового ядра нужны SciPy, MNE, scikit-learn.
- CI собирает Python 3.12 на Windows/macOS; тесты не требуют оборудования.

План интеграции: автономное ядро `app/p300`, затем отдельный рабочий поток и
приёмник Markers. Сырые timestamps остаются прежними; в P300 передаётся отдельная
копия с time_correction каждого inlet. Нет маркеров/модели — диагностическое
состояние. Научная проверка требует независимых реальных размеченных данных.

Обучение: фиксированные параметры; GroupKFold по block_id; исключение train-эпох,
чьи исходные интервалы (включая padding фильтра) пересекают test; xDAWN и
StandardScaler обучаются внутри Pipeline каждого fold. В отчёте сохраняются
индексы и идентификаторы разбиений. Финальная модель затем обучается на всей
калибровке; CV-метрики не являются оценкой независимой финальной модели.
