# Интеграция Hybrid Interface и системы Пронина

## Что объединено

Сохранена основа Hybrid Interface: `LSLReceiver`, графики каналов, массив
последнего блока, сырая CSV-запись и PNG. В окно добавлены вкладки:

Основной сценарий теперь находится во вкладке **«Единый эксперимент»**:
серия P300-проб с автоматическим запуском стимулятора и записью сессии.
Подробно: [EXPERIMENT.md](EXPERIMENT.md). Остальные вкладки:

1. **EEG — графики и CSV**: прежняя программа.
2. **P300 — анализатор Пронина**: исходный `P300AnalyzerWindow` с ERP,
   настройками, профилями, выбором цели, просмотром каналов и экспортом.
3. **Запуск и проверка**: управление оригинальным стимулятором/протоколом,
   журнал процессов и синтетическая проверка P300 без оборудования.

Источник: https://github.com/SergPronin/hybrid-bci-p300-ssvep,
коммит `4e5dc7c0165da40c1ec2eacd633032c2415e31ec`.

`p300_analysis/` и программы в `vendor/hybrid_bci/` скопированы без изменения
исходных файлов. SHA-256 каждого перенесённого файла и ID коммита находятся
в `p300_analysis/UPSTREAM.json`; тест проверяет их совпадение.
Лицензии MIT автора сохранены в обоих каталогах и включены в сборку.

## Откат прежней реализации

Удалены `app/p300`, прежний JSON-протокол, LDA/xDAWN, их тесты и отчёты
`P300_AUDIT.md` / `P300_WORK_REPORT.md`. Это реализация коммита `19fa846`,
описанная в `3d22eb1`; она остаётся доступна в истории Git. История не переписана.
`promt.md` оставлен как историческое задание.

Основа просмотра и записи соответствует функциональности `e91e83d` до
прежнего P300. Сохранены технические исправления Qt-плагинов, установки
liblsl, получения метаданных EEG и контроля обрыва потока. Закрытие окна
ожидает завершения приёмника и управляемых процессов без блокирующего wait
в главном потоке. `app/recording.py` не изменён.

Новый классификатор, новая калибровка или переобучение моделей не выполнялись.
Весь расчёт P300, включая исходную логику шаблона и привязки маркеров,
остаётся в коде Пронина.

## Точки интеграции

| Компонент | Интеграция |
| --- | --- |
| `app/viewer.py::LSLReceiver` | Один EEG-inlet; исходный `chunk_received` обслуживает графики, CSV и адаптер P300 |
| `app/bci/bridge.py::SharedEEGInlet` | Предоставляет оригинальному анализатору `info`, `pull_chunk`, `close_stream` через ограниченную очередь |
| `app/bci/panel.py::P300Panel` | Наследует исходное окно; заменяет выбор EEG на поток просмотрщика, подключение маркеров и расположение файлов |
| `p300_analysis/qt_window.py` | Оригинальный GUI, цикл анализа, ERP, профили и правила выбора цели |
| `app/bci/controls.py` | Запускает исходные `run_app.py` и `scripts/protocol_runner_gui.py` отдельным Python |
| `validation/p300_synthetic.py` | Исходная синтетическая батарея проверки без оборудования |

Ветка P300 не меняет исходные EEG-значения или timestamps в CSV просмотрщика.
При выборе входных единиц V/mV адаптер переводит амплитуды в мкВ для оригинального
анализатора. При uV значения передаются без масштабирования. Исходные временные
метки и алгоритм синхронизации Пронина сохранены, включая его поддержку грубых
timestamps источника. Дополнительная коррекция часов поверх этой логики не вводится.

Очередь EEG ограничена примерно 10 секундами (минимум 4096 отсчётов).
При переполнении анализ останавливается с сообщением, исходный просмотрщик
продолжает работу. Переход на другой EEG-поток отключает P300; повторное
подключение создаёт новый адаптер. Просроченный результат подключения маркеров
не может прикрепиться к другому EEG-потоку.

Поиск и открытие маркеров выполняются в фоновом потоке. Сам цикл ERP и отрисовка
остаются в Qt-таймере оригинального анализатора; его потоковая архитектура не
переписывалась. Производительность при высокой частоте и большом числе каналов
должна проверяться на целевой установке.

## Как работать

1. Запустите Hybrid Interface. Для реальной записи нужен внешний EEG/Signal LSL.
2. На вкладке **Запуск и проверка** выберите Python окружения Пронина и нажмите
   **Запустить стимулятор Пронина**. Откроется оригинальное окно PsychoPy.
   Ключ `--no-analyzer` предотвращает запуск второго анализатора.
3. В P300 проверьте отображаемый EEG-поток, единицы и имя маркеров
   (по умолчанию `BCI_StimMarkers`). Нажмите **Подключиться к LSL**.
4. Выберите каналы, профиль и параметры исходного анализатора, затем
   **Начать анализ**. Управляйте пробой в оригинальном стимуляторе.
5. Нажмите **Остановить анализ**, затем **Сохранить обследование**.
   Форматы исходного экспортёра: CSV/TXT/XLSX, отдельный стимул, все стимулы,
   непрерывная запись с маркерами. Путь выбирается диалогом Hybrid Interface.
6. Сырая CSV-запись во вкладке EEG запускается и останавливается независимо.

Поддерживаются оригинальные маркеры, например:

```text
-1|trial_start|target=4
-3|trial_config|...
104|on
104|off
-2|trial_end
```

Не заменяйте их прежними JSON-маркерами Hybrid Interface. ID `100..108`
и legacy `0..8` разбираются исходным кодом. Алгоритмы и последовательность
оригинального протокола не изменены.

Кнопка **Гибридный протокол Пронина** запускает его исходный операторский GUI
со всеми оригинальными этапами. Он имеет собственное управление EEG/LSL и
стимулятором; для обычного P300 достаточно встроенной вкладки и отдельного
стимулятора. Два управляемых запуска (стимулятор и гибридный протокол) одновременно
запрещены, чтобы не создавать дублирующиеся потоки маркеров. SSVEP не переносился
в новую реализацию: для него сохранены оригинальные компоненты и ресурсы MSI.

**Остановить запущенные компоненты** завершает только процессы, запущенные
этим окном. В Windows дочерние процессы принадлежат отдельному Job Object;
в macOS/Linux — отдельной группе процессов. При закрытии главного окна
компоненты также завершаются. Перед остановкой сохраняйте результаты через
оригинальный интерфейс протокола; принудительное завершение после таймаута
не гарантирует сохранение незавершённой пробы.

## Окружения

Просмотрщик и встроенный P300: Python 3.12, `requirements.txt`.
MNE и scikit-learn больше не нужны.

Исходная `psychopy==2026.1.0` требует отдельного совместимого Python;
используется Python 3.10, как в README Пронина. На Windows:

```powershell
py -3.10 -m venv .venv-pronin
.venv-pronin\Scripts\python.exe -m pip install -r requirements-pronin.txt
.venv-pronin\Scripts\python.exe scripts/install_lsl.py
```

Эти команды также находятся в `setup_pronin_windows.bat`.
В поле Python укажите `.venv-pronin\Scripts\python.exe`; при наличии рядом
с проектом/папкой dist оно подставляется автоматически. На другом компьютере
окружение стимулятора нужно установить отдельно: оно не помещается внутрь
EXE просмотрщика. Можно выбрать уже существующее окружение рабочего проекта Пронина.

`requirements-pronin.txt` сохраняет PsychoPy 2026.1.0, использует совместимый
SciPy 1.14.1 и библиотеки исходного протокола. Оригинальный `requirements.txt`
Пронина также сохранён в vendor. Для аппаратной части SSVEP нужны исходные
требования: мигалка/COM-порт и .NET 8 для MSI; они не нужны встроенному P300.

Перед запуском компонента исходники копируются в постоянный рабочий каталог:
`Документы/Hybrid Interface/upstream_runtime/<commit>/`. Там сохраняются
его настройки и результаты. Это защищает ресурсы EXE от изменений и не теряет
файлы при удалении временной папки PyInstaller. Логи встроенного P300 лежат
в `Документы/Hybrid Interface/data/`. Переменная `HYBRID_BCI_DATA_DIR` позволяет
явно сменить корневую папку, в том числе в тестах.

## Проверка без оборудования

Во вкладке **Запуск и проверка** нажмите **Проверка P300 без оборудования**.
Запускается неизменённая `run_p300_synthetic_battery` Пронина. JSON-отчёт
показывается в журнале и сохраняется в `p300_synthetic_validation.json`.
Это проверка ПО на искусственных данных; реальный EEG-поток она не создаёт.

```powershell
python -m pytest tests -q
$env:RUN_LSL_NETWORK = '1'
python -m pytest tests/test_lsl_transport.py -q
python -m app.main --self-check --report check.json
python scripts/build_app.py
python scripts/check_bundle.py
```

Первый набор включает исходные тесты Пронина, совпадение SHA-256 файлов,
сохранность CSV, адаптер очереди, исходные ERP и экспорт, отключение и устаревшие
подключения. Второй проверяет реальные локальные LSL-сокеты: исходный генератор
`SyntheticEEGInlet` передаётся через LSL одновременно в просмотрщик и P300.
Тест подключается только к собственным потокам с уникальными именами.

Реальные датасеты для завершения интеграции не требуются. Проверка на энцефалографе,
аппаратной мигалке и оценка качества распознавания на человеке не выполнялись.
Алгоритмы не объявляются заново научно валидированными по результатам этих тестов.
