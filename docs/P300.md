# Подсистема P300

Это исследовательский конвейер. Независимая проверка на реальных размеченных
данных **не проведена**. Встроенного генератора EEG и фиктивного предсказания нет.
Синтетические сигналы находятся исключительно в тестах.

## Запуск и индивидуальная калибровка

Используйте Python 3.12 и зависимости из requirements.txt. На macOS/Windows
нативная библиотека устанавливается командой
`python scripts/install_lsl.py` внутри venv. Скрипт скачивает liblsl 1.17.7 из
[официального релиза](https://github.com/sccn/liblsl/releases/tag/v1.17.7),
проверяет SHA-256 и копирует библиотеку в pylsl/lib без системной установки.
На macOS исполняемый файл framework получает локальную ad-hoc подпись для
использования как dylib. CI делает тот же шаг в изолированном Python.

1. Подключите реальный EEG/Signal с постоянной положительной nominal_srate.
   В панели P300 укажите физические единицы источника (uV, mV или V) и номера
   только EEG-каналов. Исключите EOG, триггеры и служебные каналы. Нажмите
   «Применить». Обработка использует выбранный порядок каналов; старые графики
   и CSV продолжают получать все сырые каналы.
2. Подключите внешний визуальный стимулятор с потоком Markers/Marker. Если
   найдено несколько потоков, введите точное имя и выберите поток. Модель не
   заменяет стимулятор и не управляет отображением стимулов.
3. «Записать эксперимент» создаёт уникальную вложенную папку в выбранном
   каталоге. Для новой модели нажмите «Новая калибровка». Предъявляйте известную
   участнику целевую задачу; публикуйте явные true/false target-метки для
   каждого вспыхнувшего объекта. Не выводите target из EEG или предсказания.
4. Соберите минимум три независимых экспериментальных block_id с обоими
   классами. По умолчанию нужно >=5 принятых эпох каждого класса всего и >=2
   каждого класса в тренировочной части каждого fold. Между блоками оставьте
   паузу больше длины эпохи с padding (по умолчанию >3 секунд).
5. Остановите вспышки, продолжайте EEG и дождитесь нулевой очереди эпох
   (по умолчанию >=1.8 секунды после последнего стимула). Заранее выберите
   Shrinkage LDA или xDAWN + LDA для онлайн-работы. Нажмите «Обучить обе модели».
   Проверяются оба фиксированных алгоритма, автоматически лучший не выбирается.
   Во время обучения приём, буферизация, запись и GUI продолжают работать.
6. Для онлайн-сеанса можно загрузить числовую модель NPZ. Конфигурация, единицы,
   частота, имена и порядок каналов должны точно совпадать. Target можно опустить.
   Запись нового эксперимента сохраняет загруженные модели, но очищает старую
   калибровку и накопленные ERP/оценки. Новая калибровка сбрасывает модели.
7. «Завершить эксперимент» сохраняет архив. После остановки записи просмотр
   продолжается. При смене EEG-потока эксперимент завершается, буфер и модели
   сбрасываются; параметры нужно применить заново.

Если обучение ещё выполняется, завершение записи откладывается до сохранения
моделей и отчёта. При закрытии окна приложение также ожидает обучение, сохраняя
Qt-потоки до окончания работы.

ERP показывается отдельно для каждого object_id на выбранном EEG-канале в мкВ
с числом принятых эпох. Это среднее всех принятых эпох объекта текущего этапа,
а не отдельное среднее target/non-target. Классификатор получает отдельные эпохи.

## Протокол маркеров

Один строковый канал, nominal_srate=0, тип Markers или Marker. Каждая строка —
JSON, без дополнительных полей:

```json
{
  "event_id": "participant01-session01-block01-trial01-flash001",
  "object_id": "A",
  "trial_id": "participant01-session01-block01-trial01",
  "block_id": "participant01-session01-block01",
  "objects": ["A", "B", "C", "D"],
  "target": true
}
```

- event_id уникален на всём протяжении сеанса; повторная доставка отбрасывается.
- object_id — реально предъявленный объект. objects — полный неизменный
  упорядоченный набор кандидатов данного trial (2…256 объектов).
- trial_id объединяет повторные вспышки для одного выбора. block_id задаёт
  независимый блок для оценки, а не отдельную вспышку. Все trial одного блока
  целиком попадают в один fold. Внутри trial целевой объект один и не меняется.
- target — JSON boolean, обязателен при калибровке и не используется при
  онлайн-предсказании. Строки "true"/"false" недопустимы.
- Используйте глобально различимые ID участника/сеанса/блока и для внешней оценки.
  Случайная перенумерация зависимых вспышек в разные блоки недопустима.

LSL timestamp выставляется стимулятором на фактическое начало видимого стимула
в домене lsl_local_clock источника. Маркер с временем отправки после задержки
отрисовки не позволяет восстановить физическое начало вспышки. Измеряйте
латентность дисплея/усилителя, при необходимости используйте фотодиод.
Коррекция часов LSL не компенсирует аппаратные задержки.

Каждый inlet добавляет собственный time_correction к исходным timestamps:
[описание синхронизации LSL](https://labstreaminglayer.readthedocs.io/info/time_synchronization.html).
CSV старого просмотрщика сохраняет исходные timestamps как раньше. Архив P300
содержит исходные и локальные времена и применённые поправки.
Привязка — ближайший EEG-отсчёт, допуск 0.75/sample_rate; ошибка привязки сохраняется.
Маркеры могут приходить до EEG или после EEG, пока нужная предыстория есть в буфере.

## Обработка и конфигурация

Параметры — frozen P300Config, сериализуются в session.json и модели.
«Настройки JSON» принимает объект с полями P300Config; после чтения нажмите
«Применить». sfreq, channel_names и input_unit берутся из текущего потока/панели,
остальные значения — из JSON или значений по умолчанию.
Пример дополнительных параметров:

```json
{
  "tmin": -0.2,
  "tmax": 0.8,
  "baseline": [-0.2, 0.0],
  "l_freq": 0.5,
  "h_freq": 20.0,
  "padding_s": 1.0,
  "feature_sfreq": 50.0,
  "reject_uv": 150.0,
  "flat_uv": 0.05,
  "cv_folds": 3,
  "min_repetitions": 3
}
```

По умолчанию: кольцевой буфер 30 секунд; эпоха -0.2…0.8 с; padding по 1 секунде
с обеих сторон; MNE IIR Butterworth порядка 4, 0.5–20 Гц, phase=zero;
SciPy resample_poly до 50 Гц; MNE baseline -0.2…0 с. Внутренние амплитуды — V.
Фильтр обрабатывает конечный padded-интервал каждой эпохи отдельно, одинаково
offline и online. Он использует последующие данные, поэтому результат доступен
только после tmax+padding_s. Это конвейер с задержкой, не каузальный фильтр.
Padding и частотные параметры следует обосновать для своего протокола;
граничные эффекты конечной фильтрации сохраняются.

Отбрасываются эпохи с отсутствующей предысторией, NaN/Inf, амплитудой peak-to-peak
>150 мкВ, плоским каналом <0.05 мкВ, разрывами >1.5/sample_rate или накопленным
отклонением от равномерной сетки >0.5/sample_rate. Амплитудный контроль выполняется
до и после фильтрации. Автоматическое восстановление плохих каналов, ICA и
пересчёт неизвестных физических единиц не выполняются.

Оценки — decision_function LDA, не клиническая вероятность P300. Для каждого
trial вычисляется средняя оценка объекта. Предварительный выбор появляется
только при равном числе принятых эпох всех objects, минимум 3 на каждый, и
разнице между первым и вторым местом >score_margin. При равенстве/недостатке
данных выбора нет. Этот выбор отображается в GUI, внешние команды не посылаются.
Оценки разных trial не смешиваются; хранится до 256 trial и 256 объектов ERP.

Нестандартную частоту/нерегулярный поток нельзя молча заменить на 256 Гц.
Старый просмотрщик может его отображать, но P300 потребует валидную конфигурацию.
Нет маркеров/модели — диагностическое состояние, без синтетической оценки.
При потере маркеров очищаются незавершённые эпохи и онлайн-оценки; ERP остаются.
При разрыве EEG, ошибке timestamps, синхронизации, диска или переполнении очереди
P300 останавливается с диагностикой. Для продолжения примените параметры заново.

## Обучение, утечки и воспроизводимость

Shrinkage LDA: Vectorizer → StandardScaler → LDA(lsqr, shrinkage=auto).
xDAWN + LDA: MNE XdawnTransformer(reg=oas, до двух компонент на класс) →
Vectorizer → StandardScaler → та же LDA. Priors=[0.5,0.5]. Используется публичный
[MNE XdawnTransformer](https://mne.tools/stable/generated/mne.decoding.XdawnTransformer.html).
Эта реализация не корректирует наложение ERP от соседних стимулов; протокол
стимуляции и интерпретация результатов должны это учитывать.

GroupKFold по block_id, затем purge train-интервалов, пересекающих test-интервалы,
**включая весь padding фильтра**. Классификаторы и все обучаемые преобразования
создаются заново внутри fold. Усреднения ERP не входят в обучение. Никакие
параметры обработки/артефактов не подбираются на test.
[Почему fit должен выполняться только на train](https://scikit-learn.org/stable/common_pitfalls.html).
Индексы, event_id, block_id, интервалы, исключённые эпохи, предсказания, confusion
matrix, balanced accuracy и ROC AUC сохраняются в calibration_report.json.

После CV обе финальные модели обучаются на всей калибровке. Их будущая точность
не установлена внутренней CV. Выбор алгоритма/порогов по этим CV-результатам
требует отдельной внешней проверки (или вложенной CV). Независимость участников,
сеансов и блоков должен обеспечивать дизайн эксперимента, не только программа.
Фиксированы прямые зависимости, сохраняются версии и SHA256 датасета.
Текущие алгоритмы детерминированы; random_state сохраняется для протокола,
случайное разбиение не используется. Межплатформенная побитовая идентичность
BLAS не гарантируется; числовой экспорт сверяется с исходным Pipeline.

## Архив эксперимента

- session.json — конфигурация, версии, XML/ID потоков, UTC-время начала/конца,
  число отсчётов и признак complete.
- eeg.csv — все выбранные сырые каналы, source_timestamp_s, local_timestamp_s,
  clock_offset_s; значения не очищаются, допускаются исходные NaN/Inf.
- events.jsonl — валидные полученные маркеры с метками, исходным временем и поправкой.
  Неверный JSON фиксируется диагностикой, в расчёты не попадает.
- results.jsonl — принятые/отклонённые эпохи с причинами и ошибкой привязки,
  онлайн-оценки, этапы калибровки, сведения об изменении потока маркеров.
- epochs.npz — принятые эпохи последней индивидуальной калибровки, times,
  исходные интервалы и метки. До завершения/обучения raw EEG и события уже на диске.
- calibration_report.json, shrinkage_lda.npz, xdawn_lda.npz — отчёт и модели,
  если калибровка состоялась; erp.npz — средние ERP с counts и object_id.

NPZ загружается с allow_pickle=False. При сбое процесса complete остаётся false;
raw CSV/JSONL можно исследовать и восстановить offline. Буфер ограничен, запись
raw идёт на диск. Предел 5000 калибровочных эпох и 1000 ожидающих маркеров
настраивается. Входная очередь worker ограничена 256 командами; при её
переполнении потеря данных явно обозначается, текущий архив получает complete=false.
Обучение выполняется отдельной задачей, не задерживая обработку входной очереди.

## Offline и проверка

```bash
# Повторить обработку сохранённых реальных raw EEG и явно размеченных событий:
python -m app.p300 preprocess /path/to/experiment /path/to/reprocessed.npz
# Обучить обе модели на реальной индивидуальной калибровке:
python -m app.p300 train /path/to/epochs.npz /path/to/new_model_directory
# Оценить фиксированную модель на другом реальном размеченном датасете:
python -m app.p300 evaluate /path/to/shrinkage_lda.npz /path/to/heldout.npz /path/to/evaluation.json
python -m unittest discover -s tests -v
```

Offline preprocess повторяет обработку всех явно размеченных событий архива
в хронологическом порядке; исходные статусы online-калибровки не ограничивают
новую выборку. Дубликаты и некачественные эпохи отбрасываются тем же ядром.
evaluate запрещает общие event_id и block_id с обучением и не вызывает fit.
Эта проверка не доказывает независимость данных, если ID вручную переименованы;
проверяйте происхождение и протокол записей.

Тесты проверяют буфер, clocks, события до/после EEG, артефакты, ERP, обе модели,
точный состав каждого fit, purge, воспроизводимость, сохранение и Qt-интеграцию.
Приёмники в тестах подменяются, реальное оборудование не требуется.
Успех тестов доказывает технические свойства реализации, не научную точность.

Структура: config/markers/buffer/processing/model/scoring/engine/storage/offline —
независимое ядро; worker/lsl/panel — подключение к Qt и существующему LSLReceiver.
Технический аудит до изменений: P300_AUDIT.md.
